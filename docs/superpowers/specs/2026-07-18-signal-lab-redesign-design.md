# Signal Lab 前端视觉与交互改造设计

## 目标

将 AppInsight 改造成面向产品/研究分析人员的专业数据分析工作台。核心任务链是：进入系统查看整体健康度，识别变化与风险，再下钻到领域、情感、主题、排行和原始评论。改造只在本地进行，不改变公网部署和生产数据。

## 设计方向

采用“浅色数据画布 + 局部深色品牌区”的 Signal Lab 方向。深色只用于侧栏、品牌标识和少量聚焦区域；图表、表格和密集数据统一放在浅色面板中，保证标签、坐标轴、色阶和 tooltip 的可读性。

### 颜色 token

| Token | 值 | 用途 |
| --- | --- | --- |
| `--canvas` | `#F4F7F6` | 页面背景 |
| `--panel` | `#FFFFFF` | 图表、表格、内容面板 |
| `--ink` | `#16201F` | 侧栏、主标题、强对比文本 |
| `--text-muted` | `#6E7D7A` | 说明、辅助信息 |
| `--line` | `#DCE6E2` | 边界、分割线 |
| `--accent` | `#E56B55` | 主行动、风险、重点变化 |
| `--positive` | `#2E8B78` | 正面信号、增长、健康指标 |
| `--neutral` | `#6E8190` | 中性数据、辅助系列 |
| `--warning` | `#C99B4A` | 提醒、注意事项 |

图表绘图区不使用深色底、不使用蓝紫渐变。所有组件通过统一 CSS token 获取语义色，避免每个 ECharts 配置自行定义一套颜色。

## 页面结构

### 全局工作区框架

- 侧栏保留固定导航，但升级为深色品牌锚点，显示数据源、记录数和当前工作区状态。
- 主内容增加统一工作区栏，展示当前页面、数据集、筛选摘要、更新时间和导出操作。
- `FilterBar` 从漂浮控件升级为工作区栏内的筛选区，并支持可关闭的筛选 token。
- 页面切换保留当前筛选条件，切换后滚动到顶部并执行可取消的轻量入场动画。
- 移动端保留底部导航，工作区栏支持横向滚动，筛选区改为可展开面板。

### 仪表盘首屏

首屏按阅读顺序分成四层：

1. 健康度摘要：总体正面率、平均评分、NPS、评论规模，以及基于当前数据的一句结论。
2. 变化与风险：领域情感对比、评分情感分布和关键变化，使用不对称网格突出主指标。
3. 分析入口：情感、主题、排行和评论浏览的快捷入口，点击后携带当前筛选条件。
4. 深度内容：继续复用现有图表组件，但统一卡片头部、加载态、空态和 hover 行为。

### 其他页面

情感、方面、排行、对比和浏览页面统一复用工作区栏、标题层级、面板间距和状态组件。移除各页面独立的彩色渐变 header，改为页面标签、标题、说明和当前筛选状态组成的轻量标题区。

## 交互与动效

- 首次进入：侧栏、工作区栏、指标和图表按阅读顺序错峰出现；数字使用现有计数动画但统一节奏。
- 导航切换：内容淡入并轻微上移，避免整页大幅位移。
- 筛选刷新：显示局部骨架或加载遮罩；结果更新后提供更新时间，不阻塞其他已渲染内容。
- 图表 hover：突出当前数据系列，非焦点系列降低透明度；可钻取项显示指针和明确的 pressed 状态。
- 钻取：领域、App、主题和关键词入口使用现有路由/视图切换机制，并同步筛选条件。
- 导出：优先接入现有 `/export` 接口，提供下载反馈和失败提示。
- 返回顶部、导航、筛选和导出按钮补齐 hover、pressed、keyboard focus-visible 状态。
- `prefers-reduced-motion: reduce` 下关闭非必要位移、粒子和连续循环动画。

## 数据与后端边界

优先复用现有 `/summary`、`/domain_compare`、`/nps`、`/export` 及图表接口，不新增无必要的后端接口。若前端无法可靠生成首屏结论摘要，再增加一个只读的 `/insights` 接口，输入当前筛选条件并返回结构化结论、风险项和来源指标。接口错误统一在前端状态组件中展示，不吞掉错误导致空白内容。

## 组件边界

- `App.vue`：负责全局工作区布局、页面切换、筛选状态、首屏摘要和跨页面动效。
- `FilterBar.vue`：负责筛选控件、筛选 token、加载/禁用状态和可访问性。
- 新增轻量状态组件：用于加载骨架、空结果、错误重试和导出反馈，供图表页面复用。
- 现有 ECharts 组件：保留业务数据请求和图表类型，仅统一颜色、字体、tooltip、grid 和 resize 行为。
- `theme.css` / `app.css`：集中维护 token、布局、响应式规则和全局交互状态，减少组件内重复样式。

## 验收标准

- 首屏在桌面和移动端都能先看懂整体健康度，再找到下钻入口。
- 所有图表在浅色面板中具备清晰的轴、标签、图例、tooltip 和正负语义色。
- 页面切换、筛选、加载、空数据、错误、导出和键盘 focus 都有可见反馈。
- 现有分析视图和接口继续可用，筛选条件不会在页面切换时意外丢失。
- 本地 `npm run build` 通过；本地运行后检查桌面、平板和移动端布局，确认无文本溢出、遮挡或图表空白。
- reduced-motion 模式下无持续性动效造成的阅读干扰。

## 非目标

- 不迁移 Vue、Vite、ECharts 或 Flask 技术栈。
- 不重写现有数据分析算法。
- 不修改公网部署配置，不上传或推送生产环境。
- 不为了视觉效果引入大型 UI 框架或复制参考站点的品牌样式。
